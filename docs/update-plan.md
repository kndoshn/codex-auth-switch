## 採用する方針

### 認証保存先

メインのCODEX_HOMEにある認証ファイルを利用・変更する操作は、トップレベルのcli_auth_credentials_storeにfileが明示されていることを条件とする。

公式仕様ではautoはOSの認証ストアを優先する。auth.jsonの存在だけでfileと判定する現在の方式は廃止する。設定未指定をCodexの既定値と同一視せず、本ツールの対応条件として明示設定を要求する。

| 設定・操作 | 予定する動作 |
| --- | --- |
| file | メイン認証ファイルの利用を許可する |
| keyring / auto / 未指定 | メイン認証ファイルを利用せず、file設定が必要である旨を通知する |
| 型不正・未対応の値・壊れたTOML | 安全なエラーを返し、認証ファイルとアカウント状態を変更しない |
| ls・非アクティブアカウントのremove | メイン認証保存先に依存せず、従来どおり管理データを処理する |
| 非アクティブアカウントのusage | 管理下の認証スナップショットを使用する |
| アクティブアカウントのusage | file設定を要求する。file設定で認証ファイルが欠落している場合は管理下のスナップショットへフォールバックする |
| usage --all | 保存先の問題は該当アカウントのエラーとし、他のアカウントの処理を継続する |

auto・未指定を現在利用している場合は互換性に影響する。READMEとエラーメッセージで明示設定への移行方法を案内する。ユーザーのconfig.tomlの自動書き換えやKeyringからの認証移行は行わない。

### 初回追加

初回追加の自動有効化は維持する。初回追加もuseと同様に、保存先と実行中プロセスを確認してから有効化する。

登録用の一時CODEX_HOMEはfile保存を明示してcodex loginを起動する。メインの設定や認証情報を一時ディレクトリへ複製しない。

## 実装順序

### 1. テストの日時依存を解消する

- tests/usage-service.test.tsの401再試行テストで、時刻と最終更新日時の関係を明示する。
- 日時依存のusageテストは基準時刻を固定し、テスト終了時に時計のモックを復元する。ロック待ち等のタイマーは停止させない。
- 8日経過前、8日ちょうど、8日経過後と401時の再試行を区別して検証する。
- 基準日を変えても同じ結果になることを確認する。

### 2. TOML解析と保存先判定を統一する

- src/lib/codex-auth-source.tsの行単位の正規表現解析をTOMLパーサーに置き換える。
- パーサーにはsmol-tomlを採用する予定。確認時の最新安定版は1.8.0、Node.js要件は18以上。導入時に最新版・公開元・ライセンス・監査結果を再確認する。
- トップレベルのキーのみを評価する。単一・二重引用符、引用符付きキー、コメント、CRLFを処理できるようにする。
- テーブル内の同名キー、重複キー、不正な型・値、構文エラーをテストする。
- TOMLパーサーの例外には入力断片が含まれ得るため、生の例外や設定内容をログ・エラーメッセージに出さない。ファイルパスと安全な診断情報だけを返す。
- file設定と認証ファイルの存在状態を分離する。欠落時の復元と読み取りエラーの扱いを明確にする。
- use、初回add、アクティブremove、usageで同じ判定を使用する。

### 3. 初回追加の検証とロールバックを修正する

- 初回追加と分かる場合は、ブラウザログイン開始前に保存先・プロセスの事前確認をする。
- ログイン中に状態が変わる可能性があるため、ログイン後の既存ロック内で状態・保存先・プロセスを再確認する。
- 初回ではない追加は保存のみとし、アクティブ認証を変更しない。
- 検証を終えてから管理下の認証ファイルを書き込む。
- 管理ファイル保存から有効化・state保存までをロールバック対象にする。現状で対象外の有効化書き込み失敗も含める。
- 処理前のアクティブ認証の有無を記録し、失敗時には復元または今回作成したファイルの削除を行う。
- プロセス検査が非ゼロで終了した場合も確認失敗として中断する。検査できなかった状態を「Codex未起動」と扱わない。
- Keyring拒否、auto拒否、設定未指定、実行中プロセス、プロセス検査失敗、保存失敗、ロールバック失敗を検証する。
- 拒否時に既存認証・state・管理スナップショットが変わらず、認証情報を含む孤立ファイルが残らないことを確認する。

### 4. 依存関係・CI・ドキュメントを更新する

- Valibotを修正版1.4.2以降の最新安定版へ更新し、pnpm-lock.yamlを更新する。確認時の最新安定版は1.4.2。
- 今回の問題と関係のないTypeScript、Vitest、execa等のメジャー更新は別作業とする。
- CIにpnpm checkとビルド済みCLIのヘルプ起動確認を追加する。
- 認証ファイルとプロセス検査のOS差分を確認できるよう、LinuxとmacOSでCIを実行する。
- READMEを既存の英語に合わせて更新する。file明示設定、初回自動有効化、実行中プロセスの制限、欠落時のusage動作を説明する。
- 認証スナップショットとstateの保存形式は維持し、データ移行を不要にする。

## 範囲と残る制約

Keyring対応、Codexの全設定レイヤーの再実装、使用量APIの置き換え、トークン更新の並行制御全般は今回の対象外とする。明示fileの対応条件を超える管理設定や別プロセスの起動オプションとの互換性は保証しない。

本ツールのロックはCodex自身とは共有されないため、プロセス確認後に別のCodexが起動する競合を完全には防げない。現状の「Codex終了後に切り替える」という運用条件を維持する。
